# Demo A 阶段汇总（v11 定稿）

在线开放词汇 3D 实例感知与语义地图构建，8 个 Nice-SLAM / Replica 子序列，
每场景 2000 连续帧，模拟深度相机实时采集。

> 输入 = RGB 图像 + 深度图 + 相机位姿
> 输出 = 逐帧 3D 实例分割 + 跨帧实例关联 + 可文本查询的语义地图
>
> **位姿是输入。** 本系统不含 SLAM / 回环检测。

---

## 1. 定稿指标

单进程 RTX 3090，8 场景 × 2000 帧：

| 指标 | 数值 |
|---|---|
| 平均吞吐 | **34.0 FPS**（最慢场景 32.6） |
| 检测帧 / 传播帧 | 381 ms / 10.9 ms（N=20） |
| 跨帧全局一致 3D 实例 | **231** |

Replica 网格协议（kNN 5 cm，COCO 101 点插值）：

| 口径 | AP@.25 | AP@.50 | AP@.75 |
|---|---|---|---|
| **labeled / all（论文口径）** | **45.2** | **21.6** | **7.0** |
| agnostic / all | 46.9 | 22.7 | 7.0 |
| labeled / seen | 68.1 | 33.5 | 11.3 |
| agnostic / seen | 70.7 | 35.3 | 11.3 |
| strict（只认同名，保守下界） | 23.3 | 7.7 | 2.1 |

与文献对比：

| 方法 | AP@.25 | AP@.50 | AP@.75 |
|---|---|---|---|
| OVI-MAP（CVPR 2026，离线） | 76.7 | 50.8 | 22.0 |
| **本系统 v11（在线 34 FPS）** | **45.2** | **21.6** | **7.0** |
| OVO-SLAM（RA-L 2025） | 32.8 | 23.6 | 11.1 |

**位置：AP@.25 领先 OVO-SLAM 12.4 分；AP@.50 / AP@.75 分别落后 2.0 / 4.1。**
能找到物体，但分割边界不够准。OVI-MAP 是离线全局优化方法，不同赛道。

## 2. 流水线

```
RGB-D + 位姿
  → Grounding DINO（开放词汇检测）  每 20 帧一次
  → SAM 2（掩码分割）
  → 深度反投影 → 3D 掩码
  → 几何传播（中间 19 帧，纯 numpy/CPU）
  → 跨帧实例关联（几何 + 标签门控）
  → 体素融合 → 全局一致 3D 实例地图
  → CLIP 嵌入 → 文本可查询
```

### 关键设计

**检测抽稀 + 几何传播.** 既然输入已有深度和位姿，掩码就能纯几何地从前一帧搬过来：
反投影上一帧掩码到世界坐标 → 用本帧位姿重投影 → 深度一致性检查剔除遮挡。
这一步只做矩阵乘和索引，10.9 ms，比检测帧快 35 倍。
意外收获：把间隔从 10 拉到 20，两场景均值 AP@.25 反而从 37.1 涨到 40.0 ——
逐帧独立检测产生大量一闪而过的抖动框，抽稀等于做了一次时间维度去噪。

**标签门控 `support` 档.** 跨帧关联时，家具类（table/desk/shelf…）与非家具类之间
互相否决合并，家具类之间仍允许合并。比 `strict`（全部按标签否决）好得多：
`strict` 会把 desk/table、stool/chair 拆碎，office_2 的 AP@.50 从 25.7 掉到 21.4。

**实例质量打分器.** 见下节。

## 3. 实例质量打分器（本阶段主要增益）

AP 是 PR 曲线下面积，预测集合固定时**完全由排序决定**。
融合阶段原先用 `log(1+观测帧数)` 当置信度，与真实 IoU 的 Spearman 只有 **+0.502**：

- 沙发在 359 帧里出现过，但每帧只看到一小撮体素 → 分数虚高
- 被 30 帧稳定确认的小台灯 → 分数很低

真正有信号的是**体素级多帧确认度** `fo_mean`（每个体素平均被多少帧看到），**+0.562**。

用 Ridge 把 10 维无 GT 特征映射到真实 IoU：

```
log_obs, log_fo, log_vox, fill, ext, det_max, area, fo_f5, mfvr, input_pts + 类别先验
```

**留一场景交叉验证**：预测某场景时只许用其余 7 个场景训练。

| 打分方式 | AP@.25 | AP@.50 | AP@.75 | Spearman |
|---|---|---|---|---|
| log(1+obs)（原） | 44.2 | 15.4 | 5.1 | +0.502 |
| fo_mean（无学习） | 45.0 | 18.2 | 7.1 | +0.562 |
| **Ridge α=3，留一场景 CV** | **45.2** | **21.6** | **7.0** | **+0.626** |
| ORACLE（真实 IoU 排序） | 51.7 | 28.6 | 13.5 | 1.000 |

8 个场景的 AP@.50 **全部提升**（office4 16.6→35.7，office3 12.7→22.3）。

脚本：`dump_rank_feat.py`（抽特征）→ `fit_rank.py` / `fit_rank2.py`（建模对比）
→ `apply_quality_score.py`（写回 `quality_score`）→ `patch_eval_score.py`（评测读取）。

## 4. 评测协议

早期用"逐帧 2D 掩码 vs 逐帧 GT 掩码"，与文献不可比。改用 **Replica 网格协议**
（OVI-MAP / OVO-SLAM 口径）：重建实例点云用 kNN（5 cm）投影到 GT mesh，
逐顶点算 IoU，COCO 101 点插值算 AP@25/50/75。

三个必须处理的坑：

1. Replica 是**四边形网格**，不能按三角形解析
2. 约 25% 顶点 `object_id=-1`（不属于任何面），必须排除，否则系统性撑大 union 压低 IoU
3. 墙/地板/天花板等结构性类别必须排除，否则 kNN 会把它们的顶点分给邻近实例

四种口径（labeled/agnostic × all/seen）+ strict，避免被单一数字误导。

## 5. 差距归因：239 个 GT 物体的逐个体检

逐物体算 `IoU_any`（不看类别，几何能力）与 `IoU_lbl`（类别匹配后）：

| 状态 | 数量 | 可否改进 |
|---|---|---|
| IoU ≥ 0.25 已命中 | 123 | — |
| 被覆盖但 IoU < 0.25 | 71 | **可以**（过分割 / 被大物体吞并） |
| 完全无预测点覆盖 | 37 | 受轨迹限制 |
| 纯命名错配 | 16 | 已修 5 个盆栽 |

几何上界 R@.25 = 131/239（54.8%），命名后 123。
**纯标签损失只有 16 个 —— 主要矛盾不是命名，是分割质量。**

### 死账：lamp

36 个物体（占 15%），平均顶点覆盖度 **0.08** —— 92% 的灯表面附近 5 cm 内
没有任何重建点。Nice-SLAM 轨迹是**平视**的，天花板灯基本不在视野内。
这是输入数据决定的不可达部分，与算法无关。

### 被大物体吞并（下一步最明确的方向）

room_2 一个 `shelf` 吃掉架上所有东西：

```
plate     覆盖 0.56  IoU 0.03
box       覆盖 0.87  IoU 0.03
bowl      覆盖 0.98  IoU 0.04
sculpture 覆盖 0.52  IoU 0.04
```

覆盖度极高而 IoU 极低 —— 架子与架上物品被融成一个实例。

### 评测口径 bug（已修）

`label_match` 比较的是 `norm()` 后的类名（`-` 已转空格），而同义词表里写的是
`indoor-plant` / `tv-screen` 这类连字符形式 —— **永远匹配不上**。
Replica 用 `indoor-plant` 表示盆栽、我们输出 `potted plant`，5 个盆栽白给 0 分。
修完 AP@.25 42.6 → 44.2。

注意：只补"真同义"。实测放宽近义（`cabinet↔shelf`、`vase↔pot`）会让
room_1 的 AP@.50 从 5.7 掉到 3.1 —— 错误标签抢占了 GT 的占用名额。

## 6. 已知局限

- **位姿是输入**，不含 SLAM / 回环检测
- **数据是理想化的**：Replica 深度无噪声无空洞，位姿零漂移。**退化测试尚未做** ——
  没有证据说明这些数字在真实深度相机上还成立
- **AP@.50 / AP@.75 仍落后 OVO-SLAM** 2.0 / 4.1，主因是过分割与大物体吞并
- **打分器需要标注校准**：Ridge 权重在 Replica 标注上留一场景 CV 得到，
  换到新场景能否迁移未验证
- **p95 352 ms**：平均 34 FPS 达标，但每 20 帧卡一下；
  严格意义的"每帧实时"需要异步检测器线程（架构已设计，未实现）
- **strict 口径 AP@.25 从 28.1 掉到 23.3**：打分器按含同义词的 IoU 训练，
  在只认同名的 strict 下排序不再最优
